# WebSocket Event Contract — AI Interview Assistant

Defines the message schema exchanged between the Python backend (server) and the Electron frontend (client) over a localhost WebSocket connection.

**Connection:** `ws://127.0.0.1:8765` (port configurable)
**Message format:** JSON, every message has a top-level `type` field.

---

## 1. Frontend → Backend (commands)

### `start_listening`
Starts audio capture and the processing pipeline.
```json
{ "type": "start_listening" }
```

### `stop_listening`
Stops audio capture.
```json
{ "type": "stop_listening" }
```

### `update_context`
Sent when the user updates resume or job description in the Setup screen.
```json
{
  "type": "update_context",
  "payload": {
    "resume_text": "string, extracted from uploaded PDF/doc",
    "job_description": "string, pasted by user"
  }
}
```

### `update_config`
Sent when the user changes a setting (mirrors relevant fields from `config.json`).
```json
{
  "type": "update_config",
  "payload": {
    "llm": { "answer_style": "detailed" }
  }
}
```

### `manual_answer_request`
Optional: lets the user manually trigger an answer for the current transcript buffer, bypassing automatic question detection (useful if auto-detection misses a question).
```json
{ "type": "manual_answer_request" }
```

---

## 2. Backend → Frontend (events)

### `status`
General pipeline status updates.
```json
{
  "type": "status",
  "payload": { "state": "listening" }
}
```
`state` values: `idle` \| `listening` \| `error`

### `transcript_partial`
Live, not-yet-finalized transcript text (for optional live-caption display).
```json
{
  "type": "transcript_partial",
  "payload": { "text": "so can you tell me about a time", "timestamp": 1234567890 }
}
```

### `transcript_final`
Finalized transcript segment.
```json
{
  "type": "transcript_final",
  "payload": { "text": "So can you tell me about a time you handled conflict?", "timestamp": 1234567890 }
}
```

### `question_detected`
Emitted when the Question Detection Module confirms a complete question.
```json
{
  "type": "question_detected",
  "payload": {
    "question_text": "Can you tell me about a time you handled conflict?",
    "timestamp": 1234567890
  }
}
```

### `answer_token`
A single streamed token/chunk from the LLM response. Frontend appends these in order.
```json
{
  "type": "answer_token",
  "payload": { "token": "In my", "seq": 1 }
}
```

### `answer_complete`
Signals the full answer has finished streaming.
```json
{
  "type": "answer_complete",
  "payload": {
    "question_text": "Can you tell me about a time you handled conflict?",
    "full_answer": "In my previous role...",
    "duration_ms": 2100
  }
}
```

### `error`
Any recoverable or fatal error.
```json
{
  "type": "error",
  "payload": {
    "code": "STT_INIT_FAILED",
    "message": "Could not initialize audio loopback device.",
    "fatal": false
  }
}
```
Suggested `code` values: `AUDIO_DEVICE_NOT_FOUND`, `STT_INIT_FAILED`, `LLM_API_ERROR`, `LLM_TIMEOUT`, `CONFIG_INVALID`.

---

## 3. Sequence Example (single question cycle)

```
FE → BE   start_listening
BE → FE   status { state: "listening" }
BE → FE   transcript_partial (x N, as speech streams in)
BE → FE   transcript_final
BE → FE   question_detected
BE → FE   answer_token (x N, streamed)
BE → FE   answer_complete
```

---

## 4. Implementation Notes for Claude Code

- Backend should use a single `asyncio` event loop running the WebSocket server alongside the audio/STT pipeline — avoid blocking calls in the main loop (Whisper inference should run in a thread pool or subprocess).
- Frontend should handle reconnection gracefully if the Python backend restarts (e.g., after a crash or config reload).
- All `payload.timestamp` fields are Unix epoch milliseconds, generated by the backend at time of transcription — used for session history ordering, not for display.
- Keep the schema versioned informally: if fields are added later, prefer additive changes over breaking renames so frontend/backend can be updated independently during development.
